### screens.test.js がときどきタイムアウトする件（原因：テスト環境。アプリではない）

- 症状：新しいページを開いた直後に `#app` が空のまま30秒たって、タイムアウトする（`era-jomon` や `#app > *` を待って失敗）。単体で5回実行して1回再現した
- 原因：`python3 -m http.server` の listen バックログが既定で 5（`ThreadingHTTPServer.request_queue_size`）。このアプリは1ページで20以上の ES モジュールを並行して読むため、CPU に負荷がかかっている（ほかのテストやほかのメンバーの作業と同時に動いている）と、Chromium の接続が `net::ERR_CONNECTION_RESET` で切られる。静的 import が1つ失敗するとモジュール全体が読み込まれず、アプリが起動しない
- 確認：E2E を3つ同時に走らせて負荷をかけると、`js/screens/video.js` などが ERR_CONNECTION_RESET になり再現した。バックログを 128 にすると、同じ負荷で 0件になった（252ステップ＋E2E 25件）
- 対応（tests のみ）：`tests/e2e/helpers.js` の `startEnv()` で、Python の `http.server`（`SimpleHTTPRequestHandler` + `ThreadingHTTPServer`）を `request_queue_size = 128` にして起動するように変えた。サーバーの中身は `python3 -m http.server` と同じ
- アプリ側への示唆：本番でも、Service Worker が入る前の初回訪問で電波が悪いと、モジュールの読み込みが1つ失敗しただけで画面が真っ白になる（→ BUG-018）

## BUG-010 [重要度: 低] Service Worker の更新が1回おくれ、古いエンジンと新しいデータが混ざる可能性（コードレビュー）

- 内容：`VERSION` が固定の stale-while-revalidate なので、更新後の最初の起動は古いファイルが使われる。キャッシュに無いファイル（あとから追加された lv2〜6.js など）だけはネットから新しいものが来るため、古い `battle.js` などと新しいデータ形式が混ざる。また lv2〜6.js は install 時に存在しないとキャッシュされず、オンラインで一度開くまではオフラインで遊べない（→ BUG-002B / BUG-005 につながる）
- 該当：`sw.js:2`、`sw.js:31-51`
- 対策案：リリースごとに `VERSION` を上げる、新しい SW が有効になったらリロードを促す、など
- 再現テスト：なし

## BUG-013 [重要度: 中] 読み上げ（rubySpeech）で、1〜2文字の歴史用語が誤読される

- 内容：読み上げの改善で、3文字未満のふりがな付きの語は漢字のまま読み上げエンジンに渡すようになった。このため、ふつうとちがう読み方をする短い歴史用語が誤読される
  - 「{大王|おおきみ}」→「だいおう」（lv1・lv2・lv4・lv5 の古墳時代で計10場面以上）
  - 「{明|みん}との貿易」→「めい／あかり」（lv2 室町）
  - 「{元|げん}の大軍」「元寇」→「もと」（lv1・lv2 鎌倉）
  - 「{百済|くだら}」→「ひゃくさい」（lv3 飛鳥、lv5 古墳）
  - 「むらの{長|おさ}」→「なが／ちょう」（lv4 弥生）
  - 「{唐|とう}」「{清|しん}」も、文脈によって「から」「きよし／せい」と読まれるおそれ
- 期待値：データで指定したよみのとおりに読まれる
- 該当：`js/ruby.js:26-28`（`base.length >= SPEECH_KANA_MIN` だけで判断している）
- 対策案：①漢字1文字の語は常によみにする、②データ側で「必ずよみで読む」印を付けられるようにする（例：`{明|!みん}`）、③例外リスト（王朝名・称号）を持つ、など。②がいちばん確実
- 再現テスト：`tests/unit/ruby.test.js`「rubySpeech: 特別な読み方の短い歴史用語は、よみで渡す」
- 状況（最終実行時点）：未コミットの修正で、`js/ruby.js` に「必ずよみで読む語」のリスト（`SPEECH_YOMI_WORDS`）が追加され、再現テストが通るようになった。リストに載っていない新しい語は誤読されるおそれがあるので、データを足したときはリストも見直す必要がある
- 補足：実際の読み方は OS の音声エンジンによって変わるので、iOS 実機（Kyoko）で聞いて確認するのがよい。そのほかの改善（ja-JP、pitch 1.0、Enhanced/Premium → Kyoko 等 → 最初の日本語音声の順に選ぶ、voiceschanged で選びなおす、場面の間隔が最低1.5秒＋0.25秒）は `tests/e2e/speech.test.js` で確認し、問題なし

## BUG-017 [重要度: 低] Service Worker がネットワーク優先でタイムアウトがないため、電波が弱いと起動・画面遷移が遅くなる（コードレビュー）

## BUG-018 [重要度: 低] 起動時にモジュールの読み込みが1つでも失敗すると、画面が真っ白のまま何も表示されない

- 再現手順：初回訪問（Service Worker のキャッシュがない状態）で、`js/screens/*.js` などの読み込みが1つ失敗する（電波が悪い、サーバーが接続を切る）
